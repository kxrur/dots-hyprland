# New device setup: niri + DankMaterialShell

Delta guide for adding the **niri session and DankMaterialShell (DMS)** to a machine that already has a working dots-hyprland setup (repo cloned, dotfiles deployed to `~/.config`, Hyprland session working).

Nothing here touches the Hyprland side. Tested on Arch Linux; `$REPO` below is the clone path (e.g. `~/dots-hyprland`).

## 0. Assumptions

- Arch Linux, repo cloned, submodules reachable.
- `~/.config/niri` and `~/.config/DankMaterialShell` already deployed by the usual dots workflow.
- `~/.local/bin`/`/usr/local/bin` on `PATH`, user in `input`/`i2c`/`video` groups (from the base setup).

## 1. Packages

```sh
sudo pacman -S --needed niri go ydotool ddcutil brightnessctl xdg-desktop-portal-gtk
```

- `niri` — the compositor (extra).
- `go` — building DMS. `vendor/DankMaterialShell/core/go.mod` asks for `go 1.26.5`; with the default `GOTOOLCHAIN=auto` Go fetches a matching toolchain during the build (needs network).
- `ydotool` — on-screen keyboard and movie keyboard input.
- `ddcutil` — desktop DDC/CI brightness; `brightnessctl` — laptop backlight.
- `xdg-desktop-portal-gtk` — portal backend for niri.
- Quickshell is required at runtime: check with `qs --version`. The AUR `quickshell-git` from the base setup is what this repo runs.
- PipeWire/WirePlumber are assumed present (audio, OSDs).

## 2. Submodules

```sh
cd "$REPO"
git submodule update --init --recursive
```

This pulls `vendor/DankMaterialShell` (the fork) and its nested `dank-qml-common`, and creates the `quickshell/DankCommon` symlink that the build expects.

## 3. Build and install DMS

```sh
cd "$REPO/vendor/DankMaterialShell"
make build          # CGO_ENABLED=0 go build -tags withshell -o core/bin/dms ./cmd/dms
sudo make install   # /usr/local/bin/dms + completions + systemd unit + icon + desktop entries
```

Notes:

- `make build` needs network access for Go modules (there is no `core/vendor`). Run it as your user, not with `sudo`.
- `make install` writes the unit to the invoking user's `~/.config/systemd/user/dms.service` (using `SUDO_USER`). Its `ExecStart` matches the tracked one (`/usr/local/bin/dms run --session`), so it is safe to overwrite.
- At runtime the shell QML is taken from the working tree because the tracked drop-in sets `DMS_SHELL_DIR` (see below), giving you hot reload while patching the fork.
- Binary-only alternative: `make build && sudo make install-bin`.

## 4. User service

Edit the tracked drop-in so it points at this device's clone:

`~/.config/systemd/user/dms.service.d/shell-dir.conf`

```ini
[Service]
Environment=DMS_SHELL_DIR=<absolute path to the repo>/vendor/DankMaterialShell/quickshell
```

`%h` works too, e.g. `Environment=DMS_SHELL_DIR=%h/dots-hyprland/vendor/DankMaterialShell/quickshell`.

Then:

```sh
systemctl --user daemon-reload
systemctl --user enable --now dms ydotool
```

- DMS owns `org.freedesktop.Notifications` (`dms.service` is `Type=dbus BusName=org.freedesktop.Notifications`). Do not run another notification daemon in the niri session (mako, dunst, swaync, or the end-4 `quickshell` config). The niri startup file intentionally spawns nothing shell-related.
- `ydotool` is needed for the on-screen keyboard; enable the user service (or a system unit on non-systemd setups).
- For a non-systemd/manual run, `niri/execs.kdl` has a commented `spawn-at-startup "dms" "run"` line.

## 5. Session and portals

- Log in through `niri.desktop` (installed by the `niri` package) or run `niri-session` from a TTY.
- The tracked `~/.config/xdg-desktop-portal/hyprland-portals.conf` is Hyprland-only. niri uses `xdg-desktop-portal-gtk` (plus DMS's own portal helpers). If screenshots or file pickers misbehave under niri, verify/add `~/.config/xdg-desktop-portal/portals.conf` for the niri session.

## 6. Per-device edits

These tracked values are machine-specific; adjust after deploying on a new device.

| File | Desktop | Laptop |
|---|---|---|
| `~/.config/niri/config.kdl` | laptop include commented | uncomment `include optional=true "niri/laptop.kdl"` |
| `~/.config/niri/niri/laptop.kdl` | — | verify `eDP-1` mode/scale, `caps:escape,altwin:swap_lalt_lwin`, touchpad options |
| `~/.config/niri/custom/rules.kdl` | `workspace "1".."5"` → `DP-2`, `"6".."9"` → `HDMI-A-2` | point `open-on-output` at the laptop outputs (`eDP-1` + external) |
| `~/.config/DankMaterialShell/settings.json` | `brightnessSlider.deviceName = "ddc:i2c-10"` | remove/replace with the backlight device; review battery timeouts and display settings |
| `~/.config/DankMaterialShell/monitors.json` | desktop profiles (`hom`, `wok`) | remove or recreate for this device |
| `~/.config/systemd/user/dms.service.d/shell-dir.conf` | `/home/kxr/...` | this device's repo path |
| `~/.config/niri/dms/outputs.kdl` | `DP-2`/`HDMI-A-2` modes | regenerated by DMS on start; desktop values will be replaced |
| `~/.config/hypr/**` | — | untouched; the Hyprland laptop branch keys off hostname containing `lap` |

Optional cleanup of tracked cruft before/after deploying: `settings.json.bak.*`, `.changelog-*`.

## 7. Verification

```sh
niri validate -c ~/.config/niri/config.kdl
niri msg outputs
niri msg workspaces
systemctl --user status dms
dms ipc call island status
dms ipc call audio status
```

Manual checks:

- Island shows clock + notifications; right-click empty left area opens the movie keyboard; middle-click the island opens the OSK (ydotool typing works).
- Scroll in the left/right bar gaps adjusts brightness/volume; horizontal scroll switches columns.
- Cursor hides after ~3 s idle and while typing.
- Window rules: `zen` → workspace `"2"`, `steam`/games/`FFXIVLauncher` → `"1"` (FF14 floating), `CoolerControl` → `"4"`, Heroic → `"5"`, Emulator/scrcpy floating.
- Workspaces 1–5 on the primary output, 6–9 on the second output (per your `open-on-output` config).

## 8. Maintaining the fork

Patch inside the submodule, then re-pin it in the parent:

```sh
cd "$REPO/vendor/DankMaterialShell"
git checkout -b my-change
# ... edit, test (QML hot-reloads), commit, merge to master ...
git push origin master

cd "$REPO"
git add vendor/DankMaterialShell
git commit -m "dms: bump fork (<summary>)"
```

Push the fork before the parent so the recorded commit exists remotely.

## 9. Troubleshooting

- **DMS does not start / blank bar**: `journalctl --user -u dms -f`. Most common cause is a wrong `DMS_SHELL_DIR` in the drop-in.
- **Nothing draws / `qs` errors**: check `qs --version` works and that the path in `DMS_SHELL_DIR` contains `shell.qml`.
- **Notifications do not appear**: another daemon owns `org.freedesktop.Notifications`. Stop it in the niri session.
- **No OSD/movie keyboard typing**: `systemctl --user status ydotool`, and make sure the user is in the `input` group with a re-login.
- **Build fails on Go version**: install a newer `go`, or let `GOTOOLCHAIN=auto` fetch it (network required).
- **Workspaces on the wrong monitor**: `open-on-output` names in `niri/custom/rules.kdl` do not match `niri msg outputs`.
- **Brightness slider does nothing**: desktop uses a DDC device in `settings.json`; on a laptop remove `brightnessSlider.deviceName` so it uses the backlight.
- **Portals/screenshots broken under niri**: verify the `xdg-desktop-portal` config for the niri session.
